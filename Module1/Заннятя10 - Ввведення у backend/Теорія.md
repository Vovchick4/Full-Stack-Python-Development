# Вступ

Інтернет базується на численних технологіях, серед яких HTTP (Hypertext Transfer Protocol) є однією з найважливіших. У цьому уроку ви ознайомитеся з основами HTTP та REST (Representational State Transfer), щоб отримати загальне уявлення про цю тему. Практичні приклади допоможуть вам поглибити свої знання. Ви також дізнаєтеся більше про такі важливі поняття, як автентифікація, аспекти безпеки та кешування.

### 1. Що таке HTTP?
HTTP (Hypertext Transfer Protocol) — це основний протокол зв’язку в Інтернеті. Він забезпечує обмін інформацією між веб-браузером (наприклад, Google Chrome, Firefox або Safari) та веб-сервером, на якому зберігаються веб-сайти та інші ресурси. Щоразу, коли ви вводите URL-адресу в адресний рядок браузера або натискаєте на посилання, на сервер надсилається HTTP-запит, після чого сервер повертає запитувану веб-сторінку або ресурс.

Без HTTP перегляд веб-сторінок був би неможливим, оскільки він виступає посередником між користувачем і сервером. Він забезпечує завантаження текстів, зображень, відео та іншого контенту з сервера та їх правильне відображення у браузері.

API — це абревіатура від «інтерфейс прикладного програмування», тобто набір визначень і протоколів для створення та інтеграції програмного забезпечення.

API — це спрощений спосіб підключення власної інфраструктури за допомогою розробки хмарних додатків, але вони також дають змогу ділитися даними з клієнтами та іншими зовнішніми користувачами. Публічні API мають унікальну комерційну цінність, оскільки дозволяють спростити та розширити можливості взаємодії з партнерами, а також потенційно монетизувати ваші дані (популярним прикладом є API Google Maps).

### Методи HTTP — як взаємодіють браузери та сервери?

Протокол HTTP пропонує різні методи, за допомогою яких клієнт (наприклад, браузер) може взаємодіяти з сервером. Кожен із цих методів має своє конкретне призначення:

GET – Отримує дані з сервера. Це найпоширеніший метод, який використовується для завантаження веб-сторінок.
Приклад: Коли ви відвідуєте новинний сайт, ваш браузер надсилає на сервер запит GET, щоб відобразити статті та зображення.

POST – Надсилає дані на сервер.
Приклад: Коли ви заповнюєте та надсилаєте контактну форму, введена інформація надсилається на сервер за допомогою запиту POST.

PUT – Оновлює існуючий ресурс на сервері.
Приклад: Додаток, що дозволяє змінити фото профілю, використовує запит PUT для завантаження нового зображення та заміни старого.

DELETE – Видаляє ресурс на сервері.
Приклад: У веб-додатку для управління завданнями запит DELETE може використовуватися для остаточного видалення завдання.

PATCH – Частково оновлює ресурс.
Приклад: Соціальна мережа може використовувати PATCH, щоб змінити лише текст статусу публікації, замість того, щоб знову зберігати всю публікацію.

HEAD – Отримує лише інформацію заголовка ресурсу, а не власне вміст.
Приклад: Пошукові системи використовують запити HEAD, щоб перевірити, чи існує веб-сторінка та коли вона востаннє оновлювалася, не завантажуючи весь вміст.

OPTIONS – Вказує, які методи підтримуються на сервері.
Приклад: Розробник може надіслати запит OPTIONS, щоб дізнатися, чи підтримує сервер методи PUT або DELETE.

Коди статусу HTTP — які відповіді надає сервер?
Кожен HTTP-запит супроводжується відповіддю від сервера, яка описується так званими кодами статусу. Ці коди вказують, чи був запит успішним, чи виникла проблема.

2xx (Success): Все пройшло добре. Найпопулярніший — 200 OK.

3xx (Redirection): Потрібно перейти за іншою адресою (наприклад, 301 Moved Permanently).

4xx (Client Error): Помилка на стороні користувача. 404 Not Found (не туди зайшли) або 401 Unauthorized (не залогінилися).

5xx (Server Error): Помилка в коді розробника. 500 Internal Server Error.

Чудова ідея. Це логічне продовження вашого вступу, яке перетворює абстрактні поняття на конкретну структуру, з якою розробник працюватиме в коді.

### 2. Структура HTTP-повідомлення: Headers та Body

Кожен запит від клієнта та кожна відповідь від сервера складаються з технічної частини (метаданих) та змістовної частини (даних).

#### **Headers (Заголовки)**
Заголовки — це додаткові параметри запиту або відповіді. Вони передаються у форматі `Ключ: Значення`. Вони повідомляють серверу, хто ми, який формат даних очікуємо і як з нами взаємодіяти.
* **Content-Type:** Найважливіший заголовок. Він каже серверу: «Я надсилаю тобі дані у форматі JSON» (`application/json`) або «Це звичайна HTML-форма» (`application/x-www-form-urlencoded`).
* **Authorization:** Використовується для передачі токенів або паролів, щоб сервер зрозумів, чи маєте ви доступ до ресурсу.
* **User-Agent:** Інформація про ваш браузер або програму, яка робить запит.

#### **Body (Тіло)**
Тіло повідомлення містить безпосередньо дані.
* У запитах **GET** тіло зазвичай **відсутнє** (параметри передаються прямо в URL).
* У запитах **POST, PUT, PATCH** тіло містить об'єкт (наприклад, дані нового користувача: ім'я, email, пароль).

### 3. Формат JSON: Спільна мова Backend та Frontend

Сьогодні стандартом обміну даними є **JSON (JavaScript Object Notation)**. Це текстовий формат, який легко читати людям і швидко обробляти комп'ютерам.

Приклад того, як виглядають дані користувача в тілі запиту:
```json
{
  "id": 1,
  "username": "uliana_dev",
  "is_active": true
}
```

### 4. REST: Архітектурний стиль API

**REST (Representational State Transfer)** — це не закон, а набір правил (рекомендацій), як правильно проектувати API, щоб воно було зрозумілим і масштабованим.

#### **Основні принципи REST:**

1.  **Ресурс (Resource):** У світі REST все є ресурсом. Користувачі, замовлення, фотографії — це об'єкти, з якими ми працюємо.
2.  **Унікальний ідентифікатор (URI):** Кожен ресурс повинен мати свою чітку адресу.
    * `GET /users` — отримати список усіх користувачів.
    * `GET /users/42` — отримати дані конкретного користувача з ID 42.
3.  **Використання методів HTTP за призначенням:**
    * Для створення нового ресурсу — **POST**.
    * Для читання — **GET**.
    * Для повної заміни — **PUT**.
    * Для видалення — **DELETE**.
4.  **Stateless (Безстановость):** Це означає, що сервер не зберігає стан вашої сесії між запитами.
    > **Простими словами:** Сервер "забудькуватий". Якщо ви зробили запит №1, а потім запит №2, сервер не пам’ятає вас із попереднього разу. Тому в кожному новому запиті ви повинні знову передавати свій токен авторизації.

---

### 5. Коди станів (HTTP Status Codes) — короткий довідник

Коли сервер відповідає, він завжди додає цифровий код, щоб клієнт миттєво зрозумів результат:

| Код | Значення | Що це означає? |
| :--- | :--- | :--- |
| **200** | OK | Все пройшло успішно. |
| **201** | Created | Ресурс (наприклад, новий юзер) успішно створений. |
| **400** | Bad Request | Клієнт надіслав некоректні дані. |
| **401** | Unauthorized | Потрібно залогінитися. |
| **404** | Not Found | Такої сторінки або ресурсу не існує. |
| **500** | Internal Server Error | Помилка в коді на сервері (бекенд "впав"). |

**FastAPI** — це сучасний, швидкий (високопродуктивний) веб-фреймворк для створення API на Python 3.7+. Він розроблений так, щоб бути простим у використанні та освоєнні, а також забезпечує високу продуктивність і автоматичне створення інтерактивної документації до API.

Але чому саме FastAPI?
Перш ніж заглибитися в технічні деталі, давайте розглянемо кілька причин, чому ви можете обрати FastAPI для свого наступного проєкту:

— **Швидкість:** FastAPI побудовано на базі Starlette для веб-компонентів та Pydantic для обробки даних. Це поєднання робить його одним із найшвидших фреймворків Python на ринку.

— **Простота використання:** завдяки автоматичній валідації даних, серіалізації та інтерактивній документації FastAPI є надзвичайно зручним для розробників.

— **Базується на стандартах:** FastAPI базується на стандартах OpenAPI та JSON Schema, що забезпечує сумісність із широким спектром інструментів та бібліотек.

— **Підтримка асинхронності:** FastAPI має першокласну підтримку асинхронного програмування, що дозволяє створювати додатки з високим рівнем паралельності.
