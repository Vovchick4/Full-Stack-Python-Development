
# 📚 Теоретична частина: Як мислить Git

---

## 🧠 1. Git — це не просто “збереження файлів”

Git — це **розподілена система контролю версій (DVCS)**.

Це означає:

* Кожен розробник має **повну копію репозиторію**
* Включно з усією історією змін
* Можна працювати навіть без інтернету
* Можна відновити проект у будь-який момент часу

На відміну від старих систем (SVN), Git не залежить від одного центрального сервера.

---

## 🧩 2. Git зберігає не файли — а знімки (snapshots)

Більшість новачків думають:

> Git зберігає "версії файлів"

Насправді Git зберігає:

> **стан усього проекту в конкретний момент часу**

Кожен `commit` — це повний знімок проєкту.

Якщо файл не змінювався — Git просто посилається на попередню версію (тому це дуже швидко та ефективно).

---

## 🏗 3. Архітектура Git

Всередині `.git` зберігаються:

* **Blobs** — вміст файлів
* **Trees** — структура папок
* **Commits** — метадані (автор, дата, коментар)
* **Refs** — посилання на гілки

Тобто Git — це маленька база даних.

---

## 🔁 4. Життєвий цикл зміни

Коли ти редагуєш файл, він проходить 4 етапи:

```
Modified → Staged → Committed → Pushed
```

### 🔹 Modified

Ти змінив файл у папці.

### 🔹 Staged

Ти додав його через `git add`.

### 🔹 Committed

Ти зробив знімок через `git commit`.

### 🔹 Pushed

Ти відправив зміни на GitHub.

---

## 🌳 5. Чому гілки — це головна фішка Git

У Git гілки — це не “копія проекту”.

Це просто **посилання на конкретний commit**.

Тому:

* Створення гілки — миттєве
* Перемикання — дуже швидке
* Merge — працює через алгоритм порівняння змін

---

## ⚙️ 6. Merge vs Rebase (базове розуміння)

### 🔹 Merge

Об'єднує історію двох гілок.
Залишається “розгалуження” в історії.

### 🔹 Rebase

Переписує історію так, ніби зміни були зроблені послідовно.

👉 Для новачків краще використовувати `merge`.

---

## 🌍 7. Remote-репозиторій

Коли ти підключаєш GitHub:

```bash
git remote add origin git@github.com:username/repo.git
```

`origin` — це просто ім’я віддаленого сервера.

Ти можеш мати кілька remote:

```bash
origin
upstream
production
```

---

## 🔐 8. Чому SSH краще ніж HTTPS

| HTTPS             | SSH               |
| ----------------- | ----------------- |
| Потрібен токен    | Працює через ключ |
| Можуть бути 403   | Стабільніше       |
| Часто питає логін | Не питає          |

SSH = “цифровий ключ доступу”.

---

## 📦 9. Git як інструмент DevOps

Git — це база для:

* CI/CD
* Code Review
* Pull Requests
* GitOps
* Infrastructure as Code

У реальному продакшені Git — це центр розробки.

---

## 🧨 10. Типові помилки новачків

* Робити `git add .` не розуміючи що додається
* Писати commit типу `"fix"`
* Працювати напряму в `main`
* Не створювати гілки
* Ігнорувати `.gitignore`

# 🎯 Як правильно мислити про Git

Git — це:

* 📜 історія
* 🌳 паралельні гілки
* 🧠 контроль змін
* 🔄 безпечні експерименти
* 🤝 інструмент командної роботи

## 1. Як завантажити та встановити Git

### Для Windows:

1. Перейди на офіційний сайт [git-scm.com](https://git-scm.com/).
2. Натисни **"Download for Windows"**.
3. Запусти інсталятор. **Порада:** під час встановлення можна залишати всі налаштування за замовчуванням (просто тицяй "Next"), але переконайся, що обрано пункт *Git Bash* — це зручна консоль для роботи.

### Для macOS:

Найпростіше через термінал (якщо встановлено Homebrew):
`brew install git`
Або просто введи `git --version` у терміналі — macOS сама запропонує встановити Xcode Command Line Tools, які містять Git.

---

## 2. Налаштування (Конфігурація)

Після встановлення відкрий термінал (або Git Bash на Windows) і познайомся з Git:

```bash
git config --global user.name "Твоє Ім'я"
git config --global user.email "твій_email@example.com"

```

---

## 3. Створення SSH-ключа (Твій "цифровий підпис")

Щоб GitHub (або GitLab) "впізнавав" твій комп'ютер, зробимо наступне:

### Крок A: Генеримо ключ

Введи команду в терміналі:
`ssh-keygen -t ed25519 -C "твій_email@example.com"`

> Коли запитає "Enter file in which to save", просто натисни **Enter**.
> Коли запитає "Enter passphrase", можеш знову натиснути **Enter** (залишити пустим для зручності) або ввести пароль для додаткового захисту.

### Крок Б: Копіюємо ключ

Тепер треба дістати "публічну" частину ключа. Введи:

* **Windows (Git Bash):** `cat ~/.ssh/id_ed25519.pub | clip`
* **macOS:** `pbcopy < ~/.ssh/id_ed25519.pub`

Твій ключ тепер у буфері обміну (ти його ніби "скопіював"). Він виглядає приблизно так: `ssh-ed25519 AAAA... твій_email@example.com`.

---

## 4. Додавання ключа на GitHub

1. Зайди на свій **GitHub** -> натисни на аватарку справа вгорі -> **Settings**.
2. У меню зліва обери **SSH and GPG keys**.
3. Натисни зелену кнопку **New SSH key**.
4. У полі **Title** напиши назву свого ПК (наприклад, "Мій ноутбук").
5. У полі **Key** просто встав (Ctrl+V) свій ключ.
6. Натисни **Add SSH key**.

---

## 5. Перевірка зв'язку

Введи в терміналі:
`ssh -T git@github.com`

Якщо побачиш: *"Hi [твій нік]! You've successfully authenticated..."* — вітаю! Ти налаштував усе як професіонал.

## 1. Що таке Git і навіщо він потрібен?

Без Git розробники зберігали версії файлів як `script_v1.py`, `script_v2_final.py`, `script_v2_FINAL_REAL.py`. Це шлях у нікуди.

**Git вирішує три головні проблеми:**

* **Відкат змін:** Щось зламалося? Повернися до версії, яка працювала 5 хвилин тому.
* **Командна робота:** Кілька людей можуть редагувати один і той самий файл одночасно.
* **Експерименти:** Можна створити "пісочницю" (гілку), погратися з кодом і видалити її, якщо ідея була невдалою, не зіпсувавши основний проект.

---

## 2. Три стани твого коду

Робота в Git — це як театр, де є сцена, залаштунки та архів.

| Стан | Опис |
| --- | --- |
| **Working Directory** | Твій робочий стіл. Тут ти просто пишеш код у файлах. |
| **Staging Area** | "Залаштунки". Сюди ти додаєш зміни, які хочеш включити у наступний "знімок" (коміт). |
| **Repository (.git)** | Твій архів. Тут зберігаються всі підтверджені версії твого проекту. |

---

## 3. Базові команди (Твій стартовий набір)

Відкрий термінал і давай пройдемо шлях від створення папки до першого збереження.

### Крок 1: Створення репозиторію

Зайди у папку свого проекту і напиши:
`git init`

> Це створює приховану папку `.git`. Тепер Git стежить за всім, що відбувається всередині.

### Крок 2: Перевірка статусу

`git status`

> Найкорисніша команда. Вона підкаже, які файли змінено, а які ще не "під наглядом".

### Крок 3: Додавання до "Stage"

`git add index.html` (або `git add .`, щоб додати всі файли одразу)

> Ти кажеш Git: "Підготуй ці файли до збереження".

### Крок 4: Створення коміту (Знімок версії)

`git commit -m "Додав головну сторінку"`

> **Важливо:** Завжди пиши зрозумілі коментарі в лапках, щоб через місяць зрозуміти, що саме ти зробив.

---

## 4. Гілки (Branches) — Паралельні світи

Гілки дозволяють тобі працювати над новою функцією (наприклад, "темна тема"), не чіпаючи стабільну версію сайту.

* `git branch feature-dark-mode` — створити нову гілку.
* `git checkout feature-dark-mode` — перейти на неї.
* `git merge feature-dark-mode` — об'єднати зміни з основною гілкою (main), коли все готово.

---

## 5. Git vs GitHub: У чому різниця?

Багато новачків плутають ці поняття. Все просто:

* **Git** — це інструмент на твоєму комп'ютері (двигун).
* **GitHub** — це хмарний сервіс (соціальна мережа/хостинг), де ти зберігаєш свої репозиторії та ділишся ними з іншими.
